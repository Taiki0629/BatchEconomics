# Qiita 記事執筆規約

## 構成

- **冒頭に TL;DR**（3〜5 行で結論まで言い切る）と**結論のグラフ 1 枚**を置く。読者はスクロールしなくても要点が分かること
- その後に、背景 → 実験設計 → 結果 → 考察 → 制約・注意点 → 再現手順 の順
- 「制約・注意点」を必ず設ける（n 数、モデル・時期依存、無償枠仕様の変更可能性など）

## 数値の扱い

- **数値は必ず実測値**。`40_test/` のログ・集計から機械的に導出できるものだけを載せる
- 推測・外挿・概算には明示的にラベルを付ける（例:「(推定)」「仮に〜とすると」）
- 図表の元データと生成スクリプトを対応付けておき、記事内の数値がどの run から来たか追跡できるようにする
- 料金・無償枠などの公式仕様は執筆時点の値であることを日付つきで明記する

## コード

- **実際に動いたものだけ**を載せる。記事用に書き直した抜粋も、貼る前に必ず実行して確認する
- 記事内コードと `30_development/` の乖離を作らない。抜粋なら「全文はリポジトリ参照」と誘導する
- API キーやアカウント固有情報が入り込んでいないか、貼る前に必ず確認する

## 表現

- 誇張表現を避ける。「爆速」「最強」「〜するだけ」の類は使わない
- **タイトルと中身を一致させる**。タイトルで約束したことに記事内で全部答える
- 断定できないことは断定しない。「今回の条件では」を付ける
- 他サービス・他社との比較は事実（公表仕様・実測）のみで行い、優劣の感想を書かない

## 公開前チェックリスト

- [ ] すべての数値が実測値、または推測ラベル付き
- [ ] すべてのコードが実行確認済み
- [ ] API キー・トークン・アカウント情報の混入なし
- [ ] タイトルと中身が一致している
- [ ] 制約・注意点セクションがある
- [ ] 公式仕様への言及に確認日付がある
